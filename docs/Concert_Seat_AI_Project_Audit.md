## 4. 当前 AI 调用链路

配置核查确认 OpenRouter、`inclusionai/ling-3.1-flash`、AI_MODE=auto，已配置 Key 和显式 HTTP 代理。配置存在不等于当前网络和额度正常。

- **抽取：** 管理员 text → 后端权限/输入校验 → 集中 Prompt + 已知场馆名称 → 一次模型调用 → JSON/字段校验 → 可编辑预览 → 人工保存接口 → JSON 发布记录。
- **推荐：** 当前场馆 text → 读取已发布视角 → 关联座区并每区保留第一条 → 模型解析偏好 → 本地加权排序最多十二候选 → 模型选 recordId 与评分 → 白名单/数量/重复/分数校验 → 原字段生成理由、来源、不足。
- **模式：** 强制 mock 或无 Key 使用规则；真实路径失败整体 fallback；成功 live。零候选接口直接返回 mock 标记的空推荐。前端显示模式相关提示，不能把 HTTP 200 或规则结果等同真实模型成功。
- **模型兼容：** 该 Ling 模型不带 response_format，关闭 reasoning；其他模型通常带 json_object。格式参数明确被上游拒绝时重试一次，仍校验结果。单次请求超时三十秒，不是整条推荐三十秒。

## 5. Agent 真实性结论

当前整体是 **B：Prompt 与业务逻辑编排的 AI Workflow**，抽取子模块为普通单次调用。没有模型选择工具、tool 消息回传、规划与循环执行。业务函数、两次请求、前端 Loading 和登录会话不能证明 Agent 能力。

轻量只读工具助手在技术文档中是后续方案；是否值得实现需由多步查询需求验证。不能宣称已完成 Function Calling、复杂 RAG 或自主选座 Agent。

7. **调用统计缺失。** 没有真实时延分布、Token、成本、模型质量或用户效果数据；相关指标与十五条测试是待实施方案。
